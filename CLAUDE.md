# HA Dashboard add-on repository

A Home Assistant add-on repository that packages a pre-built custom dashboard and its Home Assistant proxy API into one container on port 3002. Home Assistant installs it from this GitHub repo through the Add-on Store.

## THIS REPO IS PUBLIC

Everything committed here, including this file and every built bundle, is world-readable on GitHub, history included.

- Never commit tokens, keys, passwords, `.env` files or `/data/options.json` contents.
- Never commit private details of the Home Assistant instance (external URL, hostnames, LAN addresses), home addresses, people's names, or anything else personal.
- Run `git diff` and `git diff --cached` before every publish and read what the built bundle adds. If something private appears, stop and tell the maintainer; do not push.
- Keep this file to how the add-on is built and published. Do not add personal context here.

## Stack and layout

- `repository.yaml`: add-on repository metadata (name, url, maintainer).
- `ha_dashboard/config.yaml`: add-on manifest. Slug `ha_dashboard`, arches aarch64/amd64/armv7, port `3002/tcp`, options `ha_url` (default `http://homeassistant:8123`) and `ha_token`. The `version` field drives updates.
- `ha_dashboard/Dockerfile`: `node:22-alpine` + `jq`, installs runtime deps from `package.json` (express, cors, dotenv), copies `api/` and `dist/`, runs `run.sh`.
- `ha_dashboard/run.sh`: reads `ha_url` / `ha_token` from `/data/options.json` into `HA_BASE_URL` / `HA_TOKEN`, sets `PORT=3002`, exits if the token is empty, then `node api/index.js`.
- `ha_dashboard/api/index.js` and `ha_dashboard/dist/`: build output copied from the source project. Do not edit them here.
- `ha_dashboard/DOCS.md` (shown in the HA add-on UI) and `README.md` (install steps).
- `.gitattributes` forces LF for `*.sh` and `Dockerfile`; CRLF in `run.sh` breaks the container.

## Run it locally

There is nothing to run here. Develop and test in the source project (a separate private repo, `ha-dashboard`), which runs the same `api/index.js` serving `dist/` on port 3002.

## Publish

- Run `publish-addon.ps1` from the source project. It builds the app, replaces `ha_dashboard/dist/`, copies `api/index.js`, bumps the patch number in `ha_dashboard/config.yaml`, then runs `git add .`, commits "Publish dashboard update (vX.Y.Z)" and pushes to `main`. The push is the release.
- Because it runs `git add .`, any stray file in this folder gets published. Check `git status` first.
- The script does not touch `package.json`, `Dockerfile`, `run.sh` or the docs. Change those here by hand and bump `version` in `config.yaml`, or Home Assistant will not offer an update.
- On the device, auto-update installs new versions, but the Supervisor's store cache can lag. Add-on Store, three-dot menu, Check for updates refreshes it. This cannot be triggered with a long-lived token (the Supervisor API rejects it).

## Config and secrets

- `ha_token`: a Home Assistant long-lived access token, set only in the add-on's Configuration tab on the device. It lives in `/data/options.json` inside the add-on and must never appear in this repo.
- `ha_url`: how the container reaches Home Assistant; the internal default is correct on HAOS.

## Conventions and gotchas

- Commits are generated by the publish script; history is a linear run of "Publish dashboard update" commits.
- Keep the schema in `config.yaml` in step with what `run.sh` reads.
- Do not add a `.env` or any secret-bearing file, even git-ignored, to this folder: the publish script's `git add .` respects `.gitignore`, but there is no `.gitignore` here today.
